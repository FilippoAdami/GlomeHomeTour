# Technical Implementation Plan: 2DGS Material & Density Optimization Engine (Phase 5)

## 1. System Overview & Architectural Purpose

This document outlines the software architecture and step-by-step implementation plan for **Phase 5 (2DGS Material & Density Optimization Engine)** of the Glome Home Tour backend reconstruction system. 

Phase 5 transitions the initial metric surfel point cloud (generated by Depth Anything v3 and unprojected via `SurfelCloudInitializer`) into a fully optimized, real-time relightable **2D Gaussian Splatting (2DGS) PBR scene model**. The resulting asset features physically-based deferred materials (Albedo, Roughness, Metallic, Normals), budget-bounded Gaussian density control ($\le 400,000$ primitives), and compressed payload packaging ($\le 25\text{ MB}$) tailored for interactive WebGL/WebGPU walkthroughs and AMD RDNA4 (RX 9060 XT) HIP execution.

---

## 2. Interface Contracts & Data Flow

### Input Contract (Received from Phase 3 & 4)
* **`SurfelCloud` Data Structure (`backend/reconstruction/initialization.py`):**
  * `positions`: $(N, 3)$ `float32` in world coordinates (meters).
  * `normals`: $(N, 3)$ `float32` unit surface normal vectors.
  * `tangent_u`, `tangent_v`: $(N, 3)$ `float32` orthonormal tangent basis vectors.
  * `scales_2d`: $(N, 2)$ `float32` initial planar Gaussian radii $(\sigma_u, \sigma_v)$ (meters).
  * `colors_rgb`: $(N, 3)$ `float32` base diffuse colors in $[0, 1]$.
  * `opacities`: $(N,)$ `float32` initial primitive opacities in $[0, 1]$.
* **Keyframes & Camera Intrinsics (`backend/ingestion/package_loader.py`):**
  * `transform_matrix`: $(M, 4, 4)$ `float64` camera extrinsics ($\mathbf{T}_{c2w} \in \text{SE}(3)$).
  * `CameraIntrinsics`: $f_x, f_y, c_x, c_y, W, H$ (1080x1920 upright portrait optics).
  * `load_image_rgb()`: Keyframe RGB images.

### Output Contract (Passed to Downstream Services)
1. **`material_2dgs_checkpoint.pt`**: Full floating-point model checkpoint for backend rendering and panorama synthesis.
2. **`walkthrough_2dgs.bin` / `walkthrough_2dgs.zip`**: Compressed $\le 25\text{ MB}$ asset bundle containing 8-bit Vector Quantized (VQ) codebooks and quantized 2DGS material primitives for WebGL walkthroughs.
3. **Rasterized 4-Channel G-Buffers**: Screen-space Albedo, Normal, Roughness, and Metallic buffers consumed by `backend/floorplan/` for cross-section wall vectorization and `backend/panorama/` for 4K 360° node rendering.

## 3. ROCm / HIP Memory Safety & Stability Mandates

Because execution targets an AMD Radeon RX 9060 XT GPU (RDNA4 architecture running ROCm 6.x / HIP):
1. **Wave32 SIMD Alignment:** All HIP kernel block sizes and warp reductions must align to 32-thread SIMD wavefront execution (`__launch_bounds__(32, 8)`).
2. **Local Data Share (LDS) Caching:** Tile sorting and Gaussian intersection loops must use LDS shared memory (32KB–64KB per CU) to avoid VRAM memory bus saturation.
3. **Zero-Division & Floating-Point Bounds Guards:** All scale inversions, normal normalizations, and quaternion divisions must be explicitly clamped (`max(val, 1e-6)`) to prevent `NaN`/`Inf` propagation into HIP backward gradients.
4. **Asynchronous Memory Synchronization:** Every PyTorch C++/HIP kernel interface call must explicitly synchronize HIP streams during tile memory allocations to prevent XGMI/VRAM segmentation faults.

### Stage 1: Core Data Schemas & Parameter Activations (`model.py`)
* **Goal:** Define the `Material2DGSModel` PyTorch `nn.Module` wrapping 2D planar Gaussian primitives with physical material properties.
* **Files to Create:** [`backend/reconstruction/training/model.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/model.py)
* **Atomic Tasks:**
  1. Define `Material2DGSModel` inheriting from `torch.nn.Module`.
  2. Implement learnable parameter tensors:
     - `_xyz`: $(N, 3)$ float32 positions in meters.
     - `_rotation`: $(N, 4)$ float32 unit quaternions $(w, x, y, z)$.
     - `_scaling`: $(N, 2)$ float32 log-space 2D scales $(\ln \sigma_u, \ln \sigma_v)$.
     - `_opacity`: $(N, 1)$ float32 logit-space opacities.
     - `_albedo`: $(N, 3)$ float32 logit-space RGB diffuse colors.
     - `_roughness`: $(N, 1)$ float32 logit-space roughness values.
     - `_metallic`: $(N, 1)$ float32 logit-space metallic values.
  3. Implement forward activation property accessors:
     - `opacity = torch.sigmoid(_opacity)`
     - `scaling = torch.exp(_scaling)`
     - `rotation = torch.nn.functional.normalize(_rotation, dim=-1)`
     - `albedo = torch.sigmoid(_albedo)`
     - `roughness = torch.clamp(torch.sigmoid(_roughness), 0.04, 1.0)`
     - `metallic = torch.sigmoid(_metallic)`
  4. Implement `from_surfel_cloud(surfel_cloud: SurfelCloud)` constructor to initialize parameters directly from Phase 3 output.
* **Verification:** Unit test verifying correct initialization shapes, activation value ranges ($[0,1]$ for albedo/metallic/opacity, $[0.04, 1.0]$ for roughness), and gradient flow through all parameter tensors.

### Stage 2: PyTorch Fallback Rasterizer & G-Buffer Interface (`rasterizer_interface.py` & `pbr_shader.py`)
* **Goal:** Provide a reference PyTorch rasterizer interface and deferred PBR Cook-Torrance shader pass for CPU/CUDA/ROCm testing before custom HIP integration.
* **Files to Create:** 
  * [`backend/reconstruction/training/rasterizer_interface.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/rasterizer_interface.py)
  * [`backend/reconstruction/training/pbr_shader.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/pbr_shader.py)
  * [`backend/reconstruction/training/losses.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/losses.py)
* **Atomic Tasks:**
  1. Define `GBufferOutput` dataclass containing PyTorch tensors:
     - `albedo`: $(B, 3, H, W)$
     - `normal`: $(B, 3, H, W)$
     - `roughness`: $(B, 1, H, W)$
     - `metallic`: $(B, 1, H, W)$
     - `depth`: $(B, 1, H, W)$
  2. Implement `DeferredCookTorranceShader` evaluating image-based lighting (Split-Sum IBL environment map approximation + directional sun light):
     $$f_{\text{specular}} = \frac{D(\mathbf{H}) \cdot F(\mathbf{V}, \mathbf{H}) \cdot G(\mathbf{L}, \mathbf{V}, \mathbf{H})}{4 (\mathbf{N} \cdot \mathbf{L})(\mathbf{N} \cdot \mathbf{V})}$$
  3. Implement loss functions in `losses.py`:
     - $L_1$ Color Loss: $\| \mathbf{I}_{\text{render}} - \mathbf{I}_{\text{gt}} \|_1$
     - SSIM Loss: $1.0 - \text{SSIM}(\mathbf{I}_{\text{render}}, \mathbf{I}_{\text{gt}})$
     - Normal Map Loss: $L_{\text{normal}} = 1.0 - \langle \mathbf{N}_{\text{rendered}}, \mathbf{N}_{\text{depth\_prior}} \rangle$
     - Total Loss: $L = (1-\lambda) L_1 + \lambda L_{\text{SSIM}} + \gamma L_{\text{normal}}$
* **Verification:** Synthetic single-frame forward/backward pass test verifying gradient computation and loss convergence on CPU and GPU.

* **Atomic Tasks:**

  4. Expose PyTorch C++ bindings via `torch.utils.cpp_extension`.
* **Verification:** Benchmark comparing PyTorch fallback vs. HIP kernel. Verify $100\%$ numerical equivalence within $1e-4$ tolerance and zero memory leaks over $1,000$ continuous execution iterations on AMD RX 9060 XT.

### Stage 4: Taming-2DGS Density Control & Primitive Capping (`density_control.py`)
* **Goal:** Implement budget-aware densification, splitting, and aggressive pruning to cap total Gaussian count at $\le 400,000$ primitives.
* **Files to Create:** [`backend/reconstruction/training/density_control.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/density_control.py)
* **Atomic Tasks:**
  1. Track spatial positional gradients $\nabla_{\mathbf{p}} L$ for each Gaussian primitive.
  2. Implement `densify_and_prune()` step executed every 500 iterations:
     - **Split:** Duplicate and scale down Gaussians with large radii ($\sigma > \tau_{\text{scale}}$) and high gradients ($|\nabla_{\mathbf{p}} L| > \tau_{\text{grad}}$).
     - **Clone:** Copy small Gaussians with high gradients.
     - **Budget Cap Enforcement:** If total primitives $N_{\text{current}} \ge N_{\text{max}}$ (e.g. 400,000), disable densification and execute strictly top-k gradient pruning.
     - **Prune:** Remove primitives with opacity $o < 0.05$, aspect ratio $\sigma_u / \sigma_v > 10.0$, or positions outside the dynamic room depth ceiling.
  3. Reset opacities to $0.1$ every 3,000 iterations to eliminate invisible floaters.
* **Verification:** Run 2,000-iteration training simulation verifying that total Gaussian count monotonically stabilizes under $400,000$ without VRAM expansion.

### Stage 5: Advanced Specular Residuals & Planar Mirror Passes
* **Goal:** Add directional residual shading for window/marble glints and planar mirror reflection camera passes.
* **Files to Create/Update:** 
  * [`backend/reconstruction/training/pbr_shader.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/pbr_shader.py)
  * [`backend/reconstruction/training/planar_reflections.py`](file:///home/monday/Desktop/GlomeHomeTour/backend/reconstruction/training/planar_reflections.py)
* **Atomic Tasks:**
  1. Add lightweight 2-layer MLP specular residual module in `pbr_shader.py` to capture high-frequency view-dependent glints ($\Delta \mathbf{I}_{\text{specular}}$).
  2. Implement mirror plane detection in `planar_reflections.py`:
     - Identify high metallic ($m > 0.8$), low roughness ($\alpha < 0.15$) planar clusters.
     - Compute dominant mirror plane equation $\mathbf{n} \cdot \mathbf{x} + d = 0$.
     - Construct virtual reflection view matrix $\mathbf{M}_{\text{refl}} = \mathbf{I} - 2 \mathbf{n} \mathbf{n}^T$ for reflection texture pass.
* **Verification:** Verify mirror plane reflection matrix computation on a synthetic flat wall plane. Confirm rendering visual fidelity on glossy surface test cases.
